## Summary

Logs now show problems instead of every request, and the proxy counts its traffic: `status` reports per-model stats and the log gets a 5-minute summary.

## Changes

- A stream the provider cuts partway is logged as `upstream_broken`. Before, it was logged as a 200 success.
- Each request record has an `outcome` and, where it applies, time to first byte, the provider's request ID, the provider error type, the stop reason, token usage and the cause of each retry.
- Request records are leveled by outcome: failures are `warn`, successful generations `debug`, and catalog and token-count reads `trace`. The terminal shows `debug` by default and managed broker logs `info`. Set `runtime.log_level` to change both.
- `status` adds a `stats` field with requests, outcomes, retries, tokens and latency percentiles per route since start. The same counts are logged every 5 minutes and at shutdown.
- A full managed log moves to `.log.1` instead of being emptied, so startup and error records survive a rollover.

## Operation

No config changes are required. Request records in managed broker logs now appear only for failures, retries and hang-ups; set `"log_level": "debug"` under `runtime` to log every generation.
