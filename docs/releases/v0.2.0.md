## Summary

Ride out short provider overloads. A busy upstream no longer fails every request in a burst.

## Changes

- Add an optional per-upstream `retry` block: `{"max_attempts": N}`, from 1 to 5. The relay re-sends a request only after an upstream 503 or 529 answer, or a failed connection dial. It waits 0.25 to 4 seconds between tries with jitter, honors a `Retry-After` of up to 4 seconds, and stops waiting when the client hangs up. It never retries a timeout or a reset after the request was sent, so a generation is not billed twice.
- Show `retried ×N` in the console request log, and add `retries` to the request record.
- Add `runtime.response_header_timeout` (default `180s`, range 1s to 10m). It was a fixed 180 seconds.
- Detect a dead idle HTTP/2 connection with a ping, so a connection that died during sleep or a VPN switch is replaced in seconds, not after the header timeout.
- Log a client that hangs up as 499 instead of a 502 upstream failure.
- The example configs enable `"retry": {"max_attempts": 3}` for DeepSeek.

## Operation

Retry is off unless an upstream sets `retry`. Existing configs behave as before. There is still no fallback to another model or provider.

Claude Code retries by itself, so keep `max_attempts` small. Each try gets its own `response_header_timeout`.
