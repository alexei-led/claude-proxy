## Summary

Request diagnostics now distinguish the requested model from upstream-reported model identities.

## Changes

- Request records add `forwarded_model`, `body_reported_model` and `header_reported_model`. The terminal labels each source.
- Header attribution uses only the final upstream `x-valar-served-model` value. Body attribution uses the existing bounded Messages JSON/SSE usage reader.
- Provider model reports accept only safe ASCII identifiers of at most 128 bytes. Invalid, oversized or duplicate header reports are omitted.
- `forwarded_model` is omitted for truncated or unsafe display labels. Configured native IDs still reach the upstream unchanged.
- Aggregate stats keep configured route labels. Model reports do not change token counts or create additional requests.

These reports are upstream claims, not independent backend attestation. Missing reports remain unknown. The proxy does not infer served effort or resolve disagreements by retrying or changing routes. Authentication, endpoints, payloads, response bytes and retry policy are unchanged.

## Build security

Source builds now require Go 1.27.4 or later. CI and release builds pin Go 1.27.4. This version fixes [GO-2026-6859](https://pkg.go.dev/vuln/GO-2026-6859), an HTTP/1 server crash from a `MaxBytesReader` header race in `net/http`.

## Operation

No configuration migration is required. Restart the proxy after upgrading. For successful generation records in managed mode, set `runtime.log_level` to `debug`. The default managed `info` level still omits routine success records.
