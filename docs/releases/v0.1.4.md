## Summary

Third-party providers no longer reject Claude Code's tool schemas: the proxy removes `pattern` keywords from tool input schemas on server-key routes.

## Changes

- On `bearer`, `x_api_key` and `none` routes, the proxy removes every `pattern` keyword from `tools[].input_schema` before forwarding. DeepSeek rejected the whole request on the built-in Artifact tool's `^[^\0]*$` pattern with `400 Invalid schema for function 'Artifact'`, so mixed Anthropic and DeepSeek sessions failed at the first DeepSeek turn.
- A property named `pattern`, such as Grep's, and data keywords such as `enum`, `const` and `default` are kept. Members keep their original order.
- OAuth (Anthropic) routes still receive the original body bytes. A request with no patterns in its tool schemas is forwarded unchanged on every route.

## Upgrade

Existing configuration remains valid. Restart running proxies after upgrading; a running process keeps the old behavior.
