## Summary

A configuration can now name the claude-model-router profile it selects for its child.

## Changes

- The optional `router_provider` field sets `CLAUDE_ROUTER_PROVIDER` for the child of `run` and
  `connect`. It defaults to `model-proxy`, so existing configurations behave as before.
- Accepted names follow claude-model-router's rule: one lowercase letter first, then lowercase
  letters, digits and hyphens, at most 64 characters. The name selects `<name>-router.json` in the
  child's Claude Code profile directory. Any other value fails validation before a listener starts.
- Client settings still may not carry `CLAUDE_ROUTER_PROVIDER` or `ANTHROPIC_CUSTOM_HEADERS`: the
  configuration owns both, and the guard against overriding the proxy connection or profile is
  unchanged.

Two configurations over one Claude Code profile can now run different router profiles, for example
a GLM-only route table beside the default mixed one. Each keeps its own listener, token and
provider keys as before.

## Operation

No configuration migration is required; omit `router_provider` to keep `model-proxy`. Restart the
proxy after upgrading, because a matching configuration snapshot and installed executable define a
generation.
